外滩大会 AI 支付专题分享

支付宝 AI 支付的产品矩阵、开放路径，以及交易、信任、入口与场景之间的关系。

一、竞品关键信息

阶段性指标

当前核心指标是交易笔数，支付成功率暂非关注重点。这是阶段性指标描述，不代表没有支付风控或质量要求。

1.1 产品矩阵

全球买 Token｜TokenPay

模型资源购买与供给；AI 订阅作为持续付费场景一并呈现。

Agent 里买东西｜AI 付

即时交易、委托代理、AI 钱包 Agent。智能眼镜、耳机与具身智能属于终端应用形态，不与上述交易能力并列为一级产品。

把应用和能力变成收入｜AI 收

Vibe Pay、Skill Pay、Machine Pay，服务应用、能力和机器服务的商业化。

交易可信｜安全支撑

ACT 协议与 APASS 智能体可信身份、风控能力，为交易提供安全支撑；不是与消费、收费相同层级的交易场景。

按原文四组产品概念归类：购买资源、完成交易、实现收入，以及贯穿交易的信任能力。

AI 钱包 Agent · 核心定位

帮用户管理钱包，站在用户一边

站在用户一边的支付决策中枢。不只是替用户完成付款，而是围绕用户的目标管理任务、预算和授权，减少订阅浪费，在合适的条件下执行交易。

懂目标 · 管任务

理解意图、识别需求，拆解计划并安排执行。

控预算

智能比价、动态控制，让消费留在预算内。

守授权

遵循最小权限，满足条件后再执行，操作安全可控。

防风险

识别风险并实时拦截，在交易过程中保护用户。

看结果：减少不必要的订阅支出，合适时买到，服务购买并交付，消费经过预算与授权判断。

智能终端 AI 付：三类应用形态

智能眼镜

原文列示声纹 + 虹膜验证，连接眼镜端的消费与支付任务。

智能耳机

原文列示声纹验证，适配语音交互和免手操作。

具身智能

原文列示声纹验证，以高德动量等终端承接交易与线下执行。

1.2 2025—2027 推进路径

2025｜标杆探索

瑞幸、Rokid，以及观猹、博查等探索对象。先验证品牌 Agent、终端和交易链路。

2026｜入口与终端外拓

跟随千问、阿宝连接手机助手与智能硬件；向内连接消费任务，向外找场景。

2027｜开放生态规划

千问及支付宝开放平台方向；约 1000 万元激励金尚待核实，不视为已兑现政策。

外部探索包括瑞幸、Rokid 等标杆项目，以及观猹平台（watcha.cn）和博查 API 等开发者生态对象。

1.3 阿宝与手机助手合作

判断合作深度，要看任务是否完成，而不只是有没有入口。

L1｜卡片 + 跳转

合作方展示服务卡片，再跳回支付宝处理。

L2｜带意图拉起阿宝

将用户意图交给阿宝，继续交互和办理。

L3｜MCP 服务闭环

在合作方助手内调用服务、返回办理结果；仍需明确身份和授权边界。

现场服务与合作对象

政务、充值、缴费、积分、蚂蚁森林；手机助手与车机是重要合作入口。OPPO 接入较快是内部交流判断，不作为厂商排名。

二、论坛本次关键信息

2.1 智能体商业的 ChatGPT 时刻已经到来

开场给出的判断是，智能体正从信息工具变成交易参与者。它不仅回答问题，还会代表用户调用服务、选择商品、发起订单，并在物理世界完成取货和交付。支付网络因此需要同时服务用户、商户和 Agent。

  • 智能体互联网正在形成新的交易网络。
  • 支付需要支持机器身份、授权、预算和任务结果。
  • 具身智能让交易从线上服务进一步延伸到线下行动。

2.2 AI 支付，连接智能商业未来

AI 付不是单一支付按钮，而是一组面向用户任务、数字服务和智能终端的支付能力。用户可以直接表达目标，Agent 再结合预算、时间、地址和偏好完成选择与交易；开发者则可以通过按次、订阅和 Token 等方式实现商业化。

  • 面向用户：从明确指令升级为目标与上下文驱动。
  • 面向开发者：Vibe Pay、Skill Pay、Machine Pay 支持不同收费方式。
  • 面向终端：眼镜、耳机、机器狗等设备都可以成为支付入口。

2.3 APASS：AI 时代的信任基础设施

APASS 关注的不是一次付款是否成功，而是 Agent 在整个任务过程中是否可信：它代表谁、获得了什么授权、是否按照原始意图行动，以及出现争议后能否还原责任链。

  • 流程覆盖服务发现、委托授权、交易确认、支付核验和交付回溯。
  • 通过身份注册、持续核验和可信存证建立责任链。
  • ACT、AMP 等协议用于连接授权、商业交互、支付和多端协同。
APASS 可以作为独立能力提供。现场图明确展示两种模式：A「随收单产品开通」，签约收单时同步开通风控；B「独立集成风控服务」。独立接入不要求与收单产品捆绑，具体收费方式和价格现场图未披露。

2.4 入口与场景层

AI 原生终端、千问、智能硬件与 OPC 分别连接需求感知、服务分发、即时任务和开发者供给，共同决定支付在哪里被调用。

AI 原生终端｜感知入口

阶跃关注端云协同和上下文理解，把设备感知转成可执行任务。核心是找到服务并完成操作，而非只增加一个聊天界面。

千问｜服务连接入口

把商品、库存、物流、本地生活及用户上下文连接起来，通过开放智能体网络发现和调用服务。

智能硬件｜即时场景

眼镜、耳机、车机承接随身和免手任务。硬件负责感知交互，AI 负责理解，支付完成商业闭环，复杂任务仍需跨端协同。

OPC / 超级个体｜服务供给

开发者创造应用和 Skill，带来新的数字服务场景。持续经营需要分发、Token 供给、按次或订阅收费及结算能力。

2.5 Agentic Commerce 圆桌：核心结论

  • Agent 支付存在机会，但有人参与的消费场景仍高度依赖流量和入口。
  • 可执行权限必须与身份、授权和责任边界相匹配，发生争议要能追溯。
  • 先在高频、低风险、结果可验证的场景中检验商业可行性。
  • 开放协议有助于降低助手、商户与支付网络的接入成本。

2.6 支付展览

展台把论坛中的交易、服务入口和生态能力放进具体场景：AI 付与阿宝是重点，跨境支付、小微经营和健康硬件展示了服务覆盖的范围。

AI 付：任务、终端与开放生态

购物、条件触发交易、充值缴费等任务，把用户意图连接到授权和付款。终端展项包括智能眼镜、耳机与高德动量机器狗；AgentPay、AI 订阅等接入能力面向开发者。

蚂蚁阿宝：手机助手与服务开放

阿宝连接政务、充值、缴费、积分、蚂蚁森林和电影票等服务。卡片跳转、拉起阿宝交互与 MCP 闭环，区别在于服务由谁承接、在哪个界面完成。

Alipay+：跨境与跨终端支付

GlassPay 与 WatchPay 将支付延伸到眼镜和手表。眼镜侧关注扫码识别和确认；手表侧关注被扫支付。终端交互不同，身份确认与授权提示也要适配。

Antom：跨境商户服务

面向商户连接全球收单与不同支付方式，并延伸到经营和资金服务。与消费侧终端展示相比，重点是商户怎样接入、收款并开展跨境经营。

小微商家：生意卡、乐业卡与农业服务

服务从收款向日常经营延伸。生意卡涉及记账报税、报价和票据；乐业卡连接岗位、政策与技能服务；农业展项展示面向行业的服务入口。

蚂蚁阿福：健康服务与硬件网络

连接手表手环、动态血糖仪、饮食识别、睡眠设备及测肤硬件，让健康服务获得连续数据。与支付展项不同，重点在设备连接、用户授权和长期服务。
